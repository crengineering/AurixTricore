# BMP388.md — CJMCU-388 barometer wiring & bring-up

Wiring and bring-up notes for the **CJMCU-388** breakout (Bosch **BMP388**
pressure + temperature sensor) on the shared **I2C0** bus. This is the first
sensor brought up on the board — a learning-project stand-in for the delayed
BMP581, in the same baro role.

> **Pin-allocation SSoT:** the authoritative MCU-side pin map lives in
> **`PINNING.md` §2.3** (I2C0 SCL/SDA) and **§2.5** (electrical notes). This file
> documents the *breakout side* and the board-to-sensor wiring; it does not
> re-allocate MCU pins.

Datasheet: `Quadrocopter/doc/bst-bmp388-ds001.pdf` (Rev 1.7).
Driver: `src/bsw/Bmp388.c` / `.h`, initialised from `Cpu0_Main.c`, read at 50 Hz.

---

## 1. CJMCU-388 pad map (8 pads)

The breakout carries the BMP388 plus an onboard regulator (VIN → 3Vo) and
SDA/SCL pull-ups referenced to **VIN**.

| Pad | Meaning | I2C use |
|---|---|---|
| **VIN** | supply in (→ onboard regulator) | **3.3 V power** (see §3) |
| **3Vo** | regulated 3.3 V *output* | leave open |
| **GND** | ground | ground |
| **SCK** | serial clock | = **SCL** |
| **SDI** | serial data in / bidirectional | = **SDA** |
| **SDO** | serial data out / address LSB | **address select** (§4) |
| **CS**  | chip select (CSB) | **tie to 3V3 → I2C mode** (§4) |
| **INT** | interrupt / data-ready | leave open for now |

## 2. Wiring to the TriBoard (X702 PERIPHERALS header)

| CJMCU-388 | → TC399 | Header | iLLD pin object |
|---|---|---|---|
| SCK (SCL) | **P13.1** | X702·29 | `IfxI2c0_SCL_P13_1_INOUT` |
| SDI (SDA) | **P13.2** | X702·35 | `IfxI2c0_SDA_P13_2_INOUT` |
| VIN | **+3V3 rail** (D506) | — | — |
| GND | GND | X702 GND | — |
| CS | **+3V3** | — | interface select |
| SDO | **GND** or **+3V3** | — | address LSB |
| INT | (unconnected) | — | data-ready, optional |

Both I2C pads run in a **TTL pad-driver mode** (VIH ≈ 2.0 V) so the 5 V VEXT
port domain still reads the 3.3 V bus — see `PINNING.md` §2.5.

---

## 3. Power — VIN at 3.3 V, not 5 V

The SDA/SCL pull-ups on this breakout reference **VIN** (measured: SDI→VIN
≈ 10 kΩ). Powering VIN from **+3V3** keeps the whole bus at 3.3 V, which the
sensor tolerates and the TC399 TTL pads read reliably.

**Do not feed VIN 5 V:** it would pull SDA/SCL (and the sensor's own SDI pad) to
5 V, exceeding the BMP388 abs-max (VDDIO + 0.3 V). Tap the board's regulated
**+3V3** rail (LDO-fed, green LED D506) — *not* VCC_IN (3.5–40 V) or V_UC.

Also verify the **SCK/SCL pull-up** (SCK→VIN ≈ 10 kΩ) is present; the bus needs
one per line. If either is missing, add 4.7 kΩ to VIN.

---

## 4. Interface & address (datasheet §5)

- **CS → 3V3 selects I2C.** If CS is ever pulled low the part latches to SPI
  until a power cycle. CS has an internal ~100 kΩ pull-up (floating defaults to
  I2C), but tie it high explicitly.
- **SDO sets the address LSB and must not float:**
  - SDO → **GND** → `0x76`
  - SDO → **3V3** → `0x77`
- Driver default is **`0x77`** (`BMP388_I2C_ADDR` in `Bmp388.h`). If the chip-ID
  read fails, switch to `0x76`.

---

## 5. Bring-up milestones

1. **Chip ID** — `Bmp388_readChipId()` returns **`0x50`**. Proves pins, TTL pads,
   pull-ups, address and driver in one transaction. UART prints
   `BMP388 detected (CHIP_ID 0x50)`; a miss prints the wiring/address hint.
2. **Configure + raw read** — normal mode, ×8 pressure / ×1 temp OSR, 50 Hz ODR.
3. **Calibration + compensation** — 21-byte trim (`0x31–0x45`) → Bosch float
   formula (datasheet §9) → Pa and °C.
4. **Live in the GUI** — pressure/temperature appear on the XCP **Live Data** tab
   (`baroPressPa` / `baroTempC` in the measurement block, firmware ≥ v1.9.0).
   Sanity: **~950–1050 hPa** and roughly room temperature.

**Pre-hardware test (no sensor wired):** the firmware must boot, blink, keep
Ethernet/XCP up, and the GUI must show baro **"n/a (not detected)"** — proving
the I2C no-ACK path (`I2c.c` bounded retry) fails fast instead of hanging.
