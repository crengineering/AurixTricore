Timers on the AURIX TC399

Every timer module on the TriBoard's TC399XB, what it is for, and how to choose between them. Three families: timekeeping (STM), waveform I/O (GTM, CCU6, GPT12) and supervision (watchdogs, wake-up timer).

STM — System Timer

in use timekeeping 0xF0001000 … 0xF0001500 · STM0–STM5

One per core: a 64-bit counter free-running at ≈100 MHz from power-on. It is never started, stopped or reloaded — at 100 MHz it overflows after ~5,850 years, so software treats time as monotonically increasing, always race-free to read.

Each STM has two compare registers (CMP0/CMP1) that fire an interrupt when a selectable bit-window of the counter matches. That is its only output — no pins, no PWM.

This project uses both of its classic roles: scheduler.c polls STM0 for task timing, and CMP0 generates the 1 ms lwIP tick (updateLwIPStackISR). The rule “each core uses its own STM” is the intended pattern — per-core local time without bus contention.

GTM — Generic Timer Module

TOM in use waveform i/o 0xF0100000 · 1 instance

A timer co-processor (Bosch GTM-IP) with its own address space and clock tree. Anything that generates or measures a waveform on a pin lives here. The PWM feature uses TOM + CMU — roughly 10 % of the box. The sub-modules, with instance counts from the TC39xB register files:

CMU

clock tree

8 configurable clocks CLK0–7 plus fixed FXCLK dividers (÷1 … ÷16⁴) used by the TOMs. Every channel picks its time base here.

TBU

global time bases

Up to three shared 24-bit time bases, so channels across the GTM can act on a common notion of time (or engine angle).

TOM

6 × 16 ch · +0x8000

Simple 16-bit PWM outputs — cheap and plentiful (96 channels). Duty/period via shadow registers, glitch-free at period boundaries. Drives the P00 PWM pins since v1.7.0.

ATOM

12 × 8 ch · +0xE8000

The advanced sibling: 24-bit, per-channel modes — high-res PWM, compare against TBU time (“fire exactly at X”), serial shift-register output.

TIM

8 × 8 ch · +0x1000

Input capture: measures PWM duty & period in hardware (TPWM), pulse integration, edge counting, glitch filters. The mirror image of TOM.

CDTM

7 dead-time modules · +0xE4000

Hardware dead time between complementary outputs — what makes GTM viable for half-bridge / motor drive without software timing.

MCS

10 cores · +0xF0000

Small programmable RISC cores inside the GTM that drive TIM/TOM/ATOM registers autonomously — for waveforms too complex for fixed modes, too fast for ISRs.

DPLL + SPE

engine / BLDC

Automotive-specific: DPLL locks onto crank/cam pulses and outputs an engine-angle clock; SPE does BLDC block commutation. Rarely needed outside powertrain.

CCU6 — Capture/Compare Unit

waveform i/o 0xF0002A00 / 0xF0002B00 · CCU60, CCU61

Two instances, each with T12 (three capture/compare channels, edge- or center-aligned, hardware dead time → six complementary outputs = one 3-phase inverter) and T13 (single channel, typically triggering ADC conversions in sync with the PWM). Built-in hall-sensor mode and a trap input for emergency shutdown.

It predates the GTM and overlaps with TOM + CDTM — it survives because it is much simpler to set up for its one specialty: a small 3-phase motor, or PWM-synchronized ADC triggering without learning the GTM routing.

GPT12 — General Purpose Timer

waveform i/o 0xF0001800 · GPT120

Five 16-bit timers (T2–T6) in two blocks; timer, gated-timer, counter and concatenation modes. The architecture goes back to the C166 — for plain timing the STM is better in every way.

Its one killer feature: the incremental encoder interface. T3 (with T2/T4 as auxiliary inputs) decodes quadrature A/B signals in hardware — direction, edge counting, index handling. Wheel odometry or a motor encoder with zero CPU load.

Supervision

safety SCU · PMS standby domain

Watchdogs: one per CPU plus a global safety watchdog, windowed with password protection. This project disables all of them (CLAUDE.md rule 5) — fine for development; production firmware services them instead.

PMS wake-up timer: a small counter in the standby power domain (≈70 kHz backup clock) to wake the chip from standby. Irrelevant while the TriBoard is always-on.

Adjacent, not general-purpose: per-CPU performance counters (cycle counting for profiling) and peripheral-local baud timers in ASCLIN/QSPI.

Choosing the right timer

NeedTake
Delay, timeout, task period, timestampSTM — the one on your own core
PWM output, ordinary resolutionGTM TOM ✓ shipped in v1.7.0
24-bit PWM / time-base-aligned / serial waveformGTM ATOM
Measure frequency or duty of an inputGTM TIM
Complementary PWM with dead timeGTM TOM/ATOM + CDTM (or CCU6)
3-phase motor, simple setup, ADC syncCCU6
Quadrature encoderGPT12 (T3 incremental interface)
“Is my software still alive?”Watchdogs

The connecting idea: these modules interoperate without the CPU — GTM/CCU6 channels trigger EVADC conversions, TIM timestamps feed MCS programs, outputs reach pins through the TOUT mux. If an ISR exists only to wiggle or sample a pin at a fixed rate, there is almost always a hardware timer mode that replaces it.

Where this project stands

  • STM0–STM5 — scheduler on every core; STM0 CMP0 drives the 1 ms lwIP tick.
  • GTM TOM — P00 PWM outputs (v1.7.0), per-pin config in gpio_cfg.h, duty over XCP, validated by tools/gpio_pwm_test.py.
  • Watchdogs — deliberately disabled during bring-up.
  • Natural next step — GTM TIM input capture: a GPIO_MODE_PWM_INPUT that measures duty/frequency and publishes it in the measurements block; with a jumper wire the board then validates its own PWM without an oscilloscope.
