Layer 1

Four files, one transfer

Nothing in this path is clever, and that is the design. Each layer knows exactly one thing and hands the rest down: the task knows when, the device driver knows which register, the bus service knows how long to wait, and iLLD knows the QSPI0 register map. The one non-obvious piece is at the bottom — IfxQspi_SpiMaster_exchange() does not perform the transfer. It arms it and returns immediately; the bytes move under three interrupts, and Spi_transfer() stands there polling the channel status until they say they are done.

The handlers are three lines each and exist purely to route the vector to iLLD:

/* cppcheck-suppress misra-c2012-17.3 ; IFX_INTERRUPT emits the vector entry */
IFX_INTERRUPT(spiIsrTransmit, 0, ISR_PRIORITY_QSPI0_TX);
IFX_INTERRUPT(spiIsrReceive,  0, ISR_PRIORITY_QSPI0_RX);
IFX_INTERRUPT(spiIsrError,    0, ISR_PRIORITY_QSPI0_ER);

void spiIsrReceive(void) { IfxQspi_SpiMaster_isrReceive(&s_spiMaster); }

They keep external linkage on purpose. The vector table references them from assembly, not from C, so making them static would leave the vector entries unresolved — hence the MISRA 8.7 deviation on each one rather than a fix.

Layer 0

The bus is not electrically symmetric

Before any code matters: Port 22 sits in the TC399's 5 V VEXT domain and the IMU's absolute maximum on any pin is VDDIO + 0.3 V, so the three lines the MCU drives are divided down outside the chip. Software cannot substitute for those resistors. The single line the IMU drives has the opposite problem — 3.3 V into a pad whose default threshold is about 3.5 V — and that one is fixed in software, in one field of the pin-set struct.

const IfxQspi_SpiMaster_Pins pins =
{
    &IfxQspi0_SCLK_P20_13_OUT, IfxPort_OutputMode_pushPull,
    &IfxQspi0_MTSR_P22_10_OUT, IfxPort_OutputMode_pushPull,
    &IfxQspi0_MRSTB_P22_9_IN,  IfxPort_InputMode_noPullDevice,
    IfxPort_PadDriver_ttlSpeed1     /* <- the whole reason MISO reads back */
};

That last field is the failure that looks exactly like a dead part: clocks come out, CS asserts, every transfer reports success, and MISO reads a flat 0x00 forever. I2c.c uses the same trick for the 3.3 V sensor bus.

SCLK is P20.13, not P22.8

P22.7 and P22.8 are committed on this TriBoard — a pad self-test showed them stuck high when driven as plain GPIO with nothing attached. P20.13 is QSPI0's other usable SCLK output, and it used to be D308, CPU2's health LED, which is why Cpu2_Main.c no longer claims that pad. Note that the file-header comments in Spi.h and at the top of Spi.c still say P22.8 and P20.11 respectively; the pin-set struct above is what actually binds.

Protocol

What goes on the wire

The device protocol is one rule wide: byte 0 is the register address, and its MSB is the direction — set for a read, clear for a write. Everything after that is payload. Because SPI is full duplex, a read still has to send something for every byte it wants back, so Icm42688_readRegs() sends zeros as filler; and because the slave needs the address byte before it can answer, the first byte coming in is turnaround garbage and gets dropped.

static boolean Icm42688_readRegs(uint8 reg, uint8 *data, uint8 len)
{
    uint8 tx[1u + ICM42688_BURST_LEN];
    uint8 rx[1u + ICM42688_BURST_LEN];
    ...
    for (i = 0u; i < (1u + len); i++) { tx[i] = 0u; }      /* filler   */
    tx[0] = (uint8)((reg & 0x7Fu) | 0x80u);                /* addr | R */

    const uint16 frameLen = (uint16)len + 1u;
    ok = Spi_transfer(tx, rx, frameLen);
    if (ok != FALSE)
    {
        for (i = 0u; i < len; i++) { data[i] = rx[i + 1u]; } /* drop turnaround */
    }
}

The 14 payload bytes are six signed 16-bit axes plus temperature, sent high byte first — unlike the MPU-6050 this board replaced. Icm42688_be16() reassembles each one into a uint16 object before casting to sint16, because casting the composite shift expression directly would trip MISRA 10.8. Scaling is then a single multiply: full scale is fixed at ±16 g and ±2000 dps, so counts × (16.0f / 32768.0f) gives g, with no compensation polynomial anywhere.

Boot · runs once, before the scheduler

Bring-up, in order

  1. Spi_init()

    IfxQspi_SpiMaster_initModuleConfig() fills a config with iLLD defaults; the file overrides the three ISR priorities, sets isrProvider = IfxSrc_Tos_cpu0 so the interrupts land on core 0, sets 1 MHz, points cfg.pins at the pin set above, and disables DMA. IfxQspi_SpiMaster_initModule() then applies it and configures the pads.

  2. spi_initChannel(SPI_MODE_0)

    The channel carries the per-slave settings: baud rate, 8-bit data width, MSB first, clock polarity and phase, CS active low, and the SLSO pin. channelId is deliberately left unset — iLLD overrides it from the SLSO pin's slsoNr whenever sls.output.pin is non-NULL, so SLSO10 becomes channel 10 on its own. Setting it by hand would be silently ignored.

  3. Icm42688_init() → probe on mode 0

    Write DEVICE_CONFIG = 0x01 (soft reset), wait 10 ms, then read WHO_AM_I. That one transfer proves pins, pad modes, level shifting, CS, clock mode and driver all at once — which is why it is the bring-up gate.

  4. Fall back to mode 3 if it did not answer 0x47

    The part accepts clock mode 0 or 3 and the datasheet was not available to say which this board powers up expecting. Spi_setMode(SPI_MODE_3) re-runs spi_initChannel() only — the module stays up — and the probe repeats. Guessing wrong here is invisible without a scope: every transfer still "succeeds", and MISO reads flat 0x00 because the slave never recognised the address byte and never drove SDO.

  5. Wake, then configure

    PWR_MGMT0 = 0x0F puts gyro and accel in low-noise mode; 10 ms settle; then GYRO_CONFIG0 and ACCEL_CONFIG0 at 0x06 for 1 kHz ODR at full scale. Order matters — the ranges apply to an already-running front end. Skip the wake write and every sample reads zero while the bus looks perfectly healthy.

  6. Icm42688_debugDump(), then Ahrs_init()

    Five configuration registers plus the 14-byte block, printed over UART. WHO_AM_I = 0x47 makes everything below it meaningful; PWR_MGMT0 = 0x00 means the part is still asleep. A gyro reading 0x8000 in this dump is normal — that is its power-on value and gyro start-up takes 30 ms, so the accelerometer is valid before it is.

Steady state · 50 Hz

One transfer, start to finish

  1. The scheduler dispatches Task_Imu(). It calls Icm42688_read() unconditionally — even when the device is known absent — because that call is also the recovery probe.

  2. Icm42688_readRegs(0x1D, raw, 14) builds a 15-byte tx[]: 0x9D then fourteen zeros.

  3. Spi_transfer() checks the channel is ready and the length fits, substitutes the static sink if rx is NULL, then calls IfxQspi_SpiMaster_exchange(), which arms the transfer and returns immediately.

  4. QSPI0 pulls SLSO10 low and starts shifting. Each byte moved raises a TX or RX interrupt into spiIsrTransmit/spiIsrReceive, which hand it to iLLD to refill the FIFO and store the received byte.

  5. Meanwhile Spi_transfer() spins on IfxQspi_SpiMaster_getStatus(), comparing STM0 ticks against a 10 ms budget on every pass. At 1 MHz the 15 bytes take about 120 µs, so the deadline is roughly eighty times the real duration and only ever fires on a genuine fault.

  6. The last RX interrupt clears busy, the loop exits, CS releases, and Spi_transfer() returns TRUE after bumping s_spiOkCount.

  7. Icm42688_read() drops rx[0], assembles seven big-endian words, scales them, and fills the sample. Task_Imu() measures the real dt from SysTime_getTicks(), feeds Ahrs_update(), publishes the bias-corrected rates through measurementsSetImu(), and hands a plausibility verdict plus a liveness sum to PeriphDiag_report().

Total bus occupancy: about 120 µs out of every 20 ms, or 0.6 % of CPU0 — and unlike the I2C sensors, that time is not shared with anything else, because the IMU is alone on QSPI0.

The one rule this file exists to enforce

Every wait is bounded

iLLD ships its own wait helpers, and they spin unbounded. During the I2C bring-up that hung CPU0 forever — with both watchdogs disabled there was nothing left to recover it. So Spi.c does not use them. It polls the status itself against an STM0 deadline, and a transfer that does not finish in time fails and returns rather than never returning at all.

uint32 start = IfxStm_getLower(&MODULE_STM0);
uint32 limit = (uint32)SPI_XFER_DEADLINE_MS * SPI_STM_TICKS_PER_MS;

ok = TRUE;
while (IfxQspi_SpiMaster_getStatus(&s_spiImuChannel) == IfxQspi_Status_busy)
{
    if ((IfxStm_getLower(&MODULE_STM0) - start) > limit)   /* wrap-safe */
    {
        ok = FALSE;
        break;
    }
}

The subtraction is unsigned, so an STM rollover in the middle of a transfer produces a correct small difference rather than a huge one — the loop cannot be tricked into spinning forever by a timer wrap. Alongside it, s_spiOkCount and s_spiFailCount separate a silent slave from a wedged master, which is the distinction that cost two days on the I2C bus.

Resilience

When it breaks

A failed transfer does not just return FALSE and get retried at 50 Hz forever. Icm42688_read() owns a presence flag, and losing the device flips it — which switches the function from reading to probing, at a much lower rate. Recovery is deliberately a full re-init, not a resumed read: a part that browned out comes back awake but unconfigured, so simply resuming the burst would return zeros indefinitely.
